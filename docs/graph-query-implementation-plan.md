# Graph 查询工具包执行计划

依据：[设计方案](graph-query-design.md)。
状态：已按用户后续授权完成基础工具包实施，并移除旧兼容入口。
阶段记录与公开 API 边界见文末。

## 1. 修改边界

允许重构 Graph.Core 内部的接口、视图、匹配器和通用分析工具。
图消费者只做 API 适配、替换重复图计算及必要的测试更新。

不得改变以下架构或业务行为：

- 现有项目划分、依赖方向、优化器注册和执行顺序。
- 执行图/逻辑图的领域模型、编译边界、模板提取和资源槽分配流程。
- 各优化器的类、公开入口、输入输出和优化规则。
- 图重写、VM 发射和 XML 读写流程及已有文件格式。
- 操作完整写入白名单、张量兼容判断、资源归属和绑定规则。
- 不增加数据库、通用 LINQ 提供程序或新的消费者侧基础框架。

消费者内部允许更换查询语句与私有实现，但不迁移领域职责到 Graph.Core，
也不借机重写优化器算法。API 适配不等同于架构重组。

## 2. 执行阶段与依赖

```text
P0 基线和契约
  └─ P1 IGraphView 与相邻边命名
       ├─ P2 Filter / Match / ToGraph
       └─ P3 ReachabilityIndex
            └─ P4 消费者迁移（同时依赖 P2）
                 └─ P5 旧 API 收敛与完整验证
```

### P0：固定基线和行为契约

1. 记录工作区已有改动，不覆盖与本任务无关的变更。
2. 从项目配置确认目标框架、显式 Compile 项、测试入口。
3. 运行现有 GraphCore、执行图优化、转换和发射相关测试，记录基线。
4. 固定必须保持的行为：
   - 节点/边 ID 与端点校验，未知节点报错。
   - 过滤视图不暴露隐藏节点或相连边。
   - 平行边各自保留，邻接边按声明顺序返回。
   - 拓扑序稳定，依赖环检测保持。
   - 原 Before(a, a) 为 false；新的可达查询允许零步为 true。
5. Node(string) 按名称查询采用可选 INamedGraphNode 契约；
   不强迫生产领域节点新增或改变 Name/Id。生产消费者优先用 ID 或 Where。
6. Match 初版只支持固定线性模式。按后续要求删除旧 GraphPattern/GraphMatch，
   明确这是破坏性 API 清理，不宣称已支持旧匹配器的分支、断开模式。

验收：基线通过；契约、公开 API 范围和不变边界明确。

### P1：统一只读视图接口

1. 在 Graph.Core 增加泛型 IGraphView，Graph 实现接口。
2. 引入 EdgesToNode / EdgesFromNode，保留现有字典和只读边列表实现。
3. 将当前过滤视图适配至接口；共享视图操作只实现一次。
4. Filter、Match 等通过扩展方法共享实现，无需 GraphViewBase；
   自定义视图只实现底层读取契约，ToGraph 分别支持单视图和视图集合。
5. 将 TopologicalOrder 的算法输入改为 IGraphView，保持原算法及顺序。
6. 删除旧 View / InEdges / OutEdges，统一使用 Filter / EdgesToNode / EdgesFromNode。

验收：新入口保持原结果、异常与顺序；现有调用完成适配并能构建。

### P2：实现匹配和结果组合

1. 增加 Pattern.Create、不可变 MatchContext、Node/Edge 条件，
   限定两种减法重载；支持类型化 Where 和显式 ID。
2. Filter 返回当前范围的视图；Match 惰性返回每次匹配的 IGraphView。
3. 实现严格的节点/边可见性边界，迭代结果不引用可变的回溯工作集合。
4. 使用已有相邻边索引；显式 ID 起点不能扫描全图来定位。
5. ToGraph 分别支持单视图物化和匹配序列合并；
   保留所有命中边，同 ID 冲突明确报错，不补入未匹配边。
6. 将 20 节点原型的相关查询转为仓库正式测试。
7. 任意长度路径、Shortest/Longest、分支匹配不在这一阶段实现；
   单次多步可达查询不能用固定 Edge().Any() 替代。

验收：单点/多段/平行边、空结果、Any 短路、二次筛选和 ToGraph
范围正确；泛型类型保持；无新增领域依赖。

### P3：实现独立 ReachabilityIndex

1. 入口为 view.CreateReachabilityIndex(sources, targets)，不实现 IGraphView。
2. 两端采用 IEnumerable<TNode>，只枚举一次、去重并验证当前 view 成员。
3. 冻结构建时图范围，避免可变筛选条件令结果与索引不一致。
4. 保存起点行字典、终点列字典和 ulong 位集合；支持 ID/节点实例查询。
5. 支持空集合、有环图、零步可达；范围外端点查询报错。
6. 稀疏起点查询可逐起点遍历；针对当前优化器全节点 DAG 查询，
   复用现有反向拓扑位集合合并策略，避免简单改成每个起点重复 BFS。
7. 将选择构建策略保持在图引擎内部，不改变消费者的调用结构。
   成本包括构建临时数据，不能仅用最终压缩矩阵估算全部开销。

验收：和现有 BFS 比较全部节点对；验证 63/64/65 位边界、严格方向、
非端点中间节点、单次枚举和循环终止。全量 DAG 场景不得因迁移明显退化。

### P4：迁移消费者，保持现有架构

按下表逐类迁移，一次只改必要的图调用，避免混入其他重构。

| 消费者 | 允许的具体修改 | 必须保持 |
|---|---|---|
| ModelGraphQueries | DependencyView/DataFlowView 使用 Filter；前驱、后继、Readers/Writers 改用新相邻边名称；反复可达判断可共享索引 | 类型关系、端口/BindingId 合并校验、去重与结果顺序、资源冲突分类、边界资源规则 |
| ExecutionDependencyAnalysis | 保留现有内部类、Order、Successors、Position、Before、WithStructure；将位集合计算委托给 ReachabilityIndex | 位置表和消费者入口不变；Before(a,a) 用 ID/位置不等检查保持 false |
| DependencyReductionPostprocessor | 使用适配后的 analysis 和相邻边入口 | 去重保留首条边、替代后继判断、删边规则与批量应用流程不变 |
| TemporaryResourceReusePostprocessor | 通过原 Readers/Writers 和适配后的 analysis 查询 | 筛选、完整输出白名单、首次写入验证、末端集合、槽位选择及张量规则不变 |
| OperationTemplateSharingPostprocessor | 必要的只读图接口/查询调用适配；简单 Nodes 枚举无需强制改成 Match | 签名格式、分组、模板生成、调用替换和执行次数不变 |
| LogicalGraphDefinition/Validator | Filter 和拓扑入口适配；在重复 writer 比较中构建一次索引并复用 | 校验时机、诊断代码、终端 writer 与完成节点的含义和顺序不变 |
| ExecutionGraph | 依赖视图和拓扑入口适配 | 构造校验、异常上下文、端口/实例合法性不变 |
| ExecutionGraphRewriter | 新相邻边名称/视图接口适配 | 子图提取、替换、调用内联和全部边界重连规则不变；Match 不能代替外部边界捕获 |
| VmExecutionGraphEmitter | TopologicalOrder/视图入口适配 | 稳定指令顺序、资源分配、调用展开、公开输出不变 |
| Converter、XML 读写及其他消费者 | 搜索引用后仅适配确实受 API 签名影响的调用 | 不改变转换算法、序列化格式、领域 ID 或 schema |
| 测试及示例工具 | 更新重命名 API，引入新视图/匹配/索引测试 | 不用新索引替代全部测试 oracle；保留独立 BFS 对照，防止实现和测试一起犯错 |

Readers/Writers 已有高效邻接实现，迁移不要求强制换成 Match。
确有收益才内部替换；相同节点集合但顺序不同不能算完全兼容。
对于只需拓扑排序的验证/发射，不额外构建全量可达索引。

验收：消费者项目结构、公开优化器接口和领域职责不变；
现有优化结果及运行语义一致，边删除与资源映射可被独立测试验证。

### P5：旧 API 收敛和最终检查

1. 全仓检查旧名称、具体 GraphView 参数和旧 Pattern/Match 引用。
2. 按用户后续要求移除旧匹配器和命名别名；测试、脚本引用同步迁移。
   明确公开 API 删除和固定线性匹配的能力边界。
3. 移除确认冗余的内部代码，例如迁移后的重复可达位集合计算；
   不因新工具箱存在而删除 GraphRewriteTarget/Plan 或领域模型查询。
4. GraphAlgorithms 可缩小或重组，但拓扑能力保留；单次可达 API
   是独立工具能力，不属于旧入口别名，不因兼容层删除而移除。
5. 更新显式项目编译项、设计文档、实际用法与 API 变更说明。
6. 最后运行图相关完整测试与受影响项目构建；检查没有非图架构变更。

验收：无遗漏引用，无未说明的能力缺口，测试/构建通过，改动仅限批准范围。

## 3. 验证和性能评估

先运行覆盖当前阶段的最小测试选择器，失败时再扩大范围；
最终覆盖 GraphCore、LogicalGraphDefinition、ExecutionGraphConverter、
ExecutionGraphPostprocessor 和 VmExecutionGraphEmitter 相关测试。
实际命令依据仓库的测试运行器和目标框架确定，不盲目新增测试框架。

性能验证使用 .NET 10 单文件应用或现有基准工具，不使用 Python：

- 比较一跳资源访问、新旧固定模式搜索、全量 DAG 索引构建和重复节点对查询。
- 同时记录端到端耗时、索引构建、查询阶段、分配和矩阵内存。
- 同一输入/端点/结果数量，预热并重复测量；区分少量查询与大量查询。
- 20 节点图只验证正确性，额外使用代表性真实执行图及较大合成 DAG。
- 不用“Any 返回首个结果”冒充“全部匹配”性能，也不忽略 ToGraph 的物化成本。
- 若普遍出现明显退化，先调整图引擎策略；不改变消费者业务规则来掩盖退化。

## 4. 交付与停止条件

交付内容：Graph.Core 新 API 与实现、必要的消费者调用适配、正式测试、
性能比较结果和已同步文档。

遇到以下情况不直接扩大任务范围：

- 需要改变优化器流程/公共接口或项目依赖架构。
- 需要修改节点名称等领域模型语义才能接入。
- 需要删除尚无完整替代的公共 API。
- 查询结果、顺序、错误处理或优化安全性发生无法解释的变化。

这些情况应先明确偏差，选择兼容路径；不能把“简化架构”作为改动
图引擎之外程序架构的理由。

## 5. 阶段完成记录

| 阶段 | 结果 |
|---|---|
| P0 | 图相关既有测试基线 66/66 通过；确认旧模式的一般结构能力及 Before 自身为 false 的契约 |
| P1 | IGraphView、Filter、新相邻边名称及接口化图算法已实现；保留原字典/列表索引 |
| P2 | 线性 Match、不可变模式、精确匹配视图、ToGraph 已实现；18 个查询迁入正式测试 |
| P3 | 独立 ReachabilityIndex 已实现，支持有环遍历与密集 DAG 传播、范围校验及快照 |
| P4 | 模型查询、优化器内部分析、逻辑图 writer 比较和图重写邻接调用完成适配；其他发射/转换消费者通过共享入口取得能力，无需改其架构 |
| P5 | 按后续要求删除旧兼容 API，保留单次 BFS 独立能力；清除优化器内重复位集合计算；完成回归及 .NET 性能比较 |

实际选择：

- IGraphView 只声明底层读取能力；查询操作保持扩展方法，不引入
  GraphViewBase。集合 ToGraph 合并匹配结果，单视图 ToGraph 物化快照。
- Graph.Core 顶层类型拆为独立文件，并同步显式项目编译项。
- 删除没有消费者的节点、边可选基类，保留 IGraphNode / IGraphEdge 契约。
- 没有强制重写 Readers/Writers 为 Match，保留更便宜的邻接查询和原顺序。
- 删除 GraphPattern/GraphMatch、View/InEdges/OutEdges，迁移仓库内实际调用；
  固定线性 Match 不宣称支持旧匹配器的分支、断开模式。
- 单次 BFS 是独立查询能力，保留用于有环图和一次性可达查询。
- GraphNodeId 增加 string 隐式转换，保持 Node(string) 的名称匹配语义。
- 图引擎及本次修改的消费者声明补齐 XML 文档，包括参数、泛型参数、
  返回值和关键异常；通过文档编译与声明参数覆盖检查。
- 图消费者的项目划分、优化流程、领域模型、序列化格式没有调整。
- 性能脚本和实测限制见设计文档第 7 节；不是模型端到端推理基准。
