# Model-neutral foundation migration

## Baseline

The pre-refactor solution builds with .NET SDK 10.0.401. External models are read-only inputs from `D:\GithubRoot\rwkvcpp\tests`; no external repository files are changed.

Available validation inputs include RWKV-6 and RWKV-7 FP32/FP16 tiny models and expected logits. Quantized files and earlier RWKV versions are not part of this migration's supported execution scope. Phi model weights are unavailable; real Phi4 inference remains pending.

The initial targeted run contained 67 tests: 62 passed and 5 failed before foundation changes. Existing failures:

- `InstructionCollectionTests.CollectionsExposePrecisionAndExtensibleArchitecture`: expected 6 instruction collections, actual 7.
- `InstructionCollectionTests.GeneratorCatalogIsIndependentFromBackendCatalog`: expected 6 instruction collections, actual 7.
- `InstructionCollectionTests.HalfCollectionExecutesEveryInstructionOnCpuAndGpu`: `core.affine`, `core.matrix-multiply`, and `core.bias-add` fail generated CPU compilation with CS1503 for Half/float span conversions.

Results are recorded in the ignored `artifacts/model-neutral-baseline` directory. These failures must be distinguished from migration regressions; they are not treated as passing tests.

## Numeric snapshots

`ModelNeutralityBaselineTests` exercises all four tiny models with tokens `[34, 105, 110, 32, 116]` and verifies snapshot-restored continuation with token 101. Each frame includes logits, state schema, ordered state names, and state values. The fixture includes the source model SHA-256. Initial state is zero and the CPU execution configuration is unchanged. No tokenizer is required.

Set `SHARPINFERENCE_BASELINE_DIRECTORY` to an absolute directory under the workspace and `SHARPINFERENCE_CAPTURE_BASELINE=1` only for the pre-refactor capture. Capture uses create-new semantics and refuses to overwrite previous snapshots. Unset the capture flag for all subsequent comparisons. Numeric comparison requires finite values and uses `absolute=1e-5` and `relative=1e-5` per element; snapshot restoration on the same backend requires exact equality.

Supply external model paths using `-p:RwkvTestModelDirectory=D:\GithubRoot\rwkvcpp\tests`. Snapshots and TRX files are local validation artifacts, not bundled model weights.

## Dependency migration checklist

- Abstractions: move RWKV metadata, recurrent-state and architecture contracts out; provide model-independent tensor types and tensor lookup without mandatory language-model dimensions.
- Core: move World tokenizer, vocabulary and architecture detection to model modules; move GGML format reading to a format project; separate generic generation from model defaults.
- Graphs: remove RWKV constructors and model/state interfaces; use resource descriptors, registered operation contracts and explicit state ABI.
- RWKV-6/RWKV-7: retain independent graph providers and own recognition, dimensions, bindings and model-specific validation.
- Phi4: expose model-owned graph/operation registrations; validate contracts with synthetic data now and real weights later.
- Instructions/VM: consume registered operator semantics and graph bindings, not model names; reject unsupported targets explicitly.
- Runtime: remove concrete architecture/backend creation and platform dependencies; isolate CPU/D3D12 composition and diagnostics in adapters.
- Applications: register model and backend modules explicitly; derive scheduling from execution capabilities rather than backend aliases.

## Final validation requirements

Shared project dependency checks must reject architecture/backend project references and model-specific public contracts. An independent non-language test model must exercise custom operators, graph resources and state without adding branches to shared code. RWKV numeric comparisons use the captured tiny-model fixtures. GPU and cross-platform execution are reported only when actually run. Phi4 real-weight numeric, multimodal and end-to-end generation checks remain pending until model resources are supplied.

## Current implementation status

- Plan steps 1 through 12 are complete within the planned available-input scope. Abstractions no longer exports RWKV contracts or requires language-model dimensions on tensor catalogs. All tensor consumers use `TensorDataType`. RWKV family contracts and adapters are in `SharpInference.Models.Rwkv`. This is not a claim that all historical tests or unavailable real-model/platform checks pass.
- Each concrete model family now has one project. `Models.Rwkv` contains common contracts/tokenizer/resources, independent RWKV6/7 graph modules under `Architecture`, and explicit runtime helpers under `Runtime`. `Models.Phi4` contains architecture, operation contracts, CPU/D3D12 instructions and direct comparison components. Existing public namespaces remain unchanged. Phi4 multi-targets portable `net10.0` and `net10.0-windows10.0.19041.0`; Windows implementations and dependencies are excluded from the portable target. Shared instructions, backend adapters and format readers remain separate and never reference concrete model assemblies.
- `PortableGraphModel` and backend session contracts use `IModel`/`IModelState`; Graphs no longer references an architecture or backend project. `INamedFloat32ModelState` is an explicit optional capability, not the general state contract.
- `GraphTensorState` stores descriptor-based Byte, Int32, UInt32, FP16 and FP32 buffers, with model-supplied initial bytes, independent clones and reset-to-initial behavior. Token-session adapters use the explicit FP32 state implementation; `VmTensorGraphSession` separately executes descriptor-bound byte IO and typed state without token semantics.
- `GraphModelSignature` exposes only model type, opaque state ABI, dimensions and attributes. RWKV projections and legacy JSON/XML readers are model-owned; legacy reads require an explicit adapter.
- Core now only references Abstractions. Tokenizer, vocabulary and recognition are in the RWKV family project; GGML reading is in `Models.Ggml`. Model-neutral sampling, stop matching and generation sessions are in `Generation`.
- RWKV-6 and RWKV-7 independently provide `IModelGraphModule` entries. Explicit module registration reports unknown, duplicate and ambiguous architecture recognition without model switches in shared code.
- Generated RWKV and Phi4 logical graphs use explicit `<node-id>_output` IDs for local results (for example, `portable.01843_output`); composition prefixes node and result references together. Public IO names, weight binding keys and state ABI names remain unchanged. This is a model-builder convention, not a serialization rewrite or a restriction on user-supplied graphs.
- Model operators can supply `IGraphOperationLowerer` expansions preserving external IO/state/resource contracts or explicit `GraphInstructionBinding` mappings through `InstructionRegistry`. Both paths have actual compiled CPU execution tests; native mappings cannot override standard tensor semantics.
- Step 9 is complete. Descriptor-based state/IO validation supports Byte, Int32, UInt32, FP16 and FP32; unknown target adapters are rejected. Backend preparation no longer applies the token contract to every graph. Generic byte-IO sessions execute a compiled non-token CPU graph; typed integer state restores after execution failure or cancellation and resets to model-supplied initial bytes. Host state is committed only after all result reads succeed. Active graph sessions prevent replacing the prepared program and are disposed before backend resources. Token sessions require an explicitly declared prefill entry.
- Step 10 is complete. `ProcessorPipeline` uses `ModelMetadata`, an explicit model-module registry, module-owned validators/lowerers and graph weight descriptors; it no longer detects RWKV dimensions or constructs an FP32 state ABI. Non-text graphs declare tensor input capabilities and expose `ITensorProcessorSession` through `IProcessor.CreateSession()`; the token-session adapter remains an optional, explicit capability.
- Shared Runtime targets `net10.0` and does not reference model architectures, concrete backends, backend instruction implementations or runtime adapters. CPU construction and instruction defaults are in `Runtime.Cpu` (`net10.0`); D3D12 construction, device ownership and typed statistics are in `Runtime.D3D12`. Shared Runtime exposes only `IVmBackendDiagnostics` metrics and backend-supplied execution capabilities. RWKV convenience factories are in `Models.Rwkv/Runtime`.
- Generic model weights are initialized into shared VM global resources before the model reader closes. Tensor sessions share the prepared globals, retain independent invocation/state resources, and do not require full CPU-owned tensor catalog copies. Disposing one session does not release another session's weights; backend shutdown releases sessions before shared globals and device resources.
- Step 11 is complete. `SharpInference.Applications.RwkvApplicationComposition` owns explicit RWKV6/7 module registration, configuration aliases and concrete backend selection. RWKV runtime helpers in `Models.Rwkv` do not reference configuration or backend adapters and require an explicit backend/catalog. Web API, Integration, DeploymentTest, PrefillExperiment, VM Tool/Template, benchmarks, existing tests and direct Phi4 comparison implementations now inject target-specific instruction providers and backend adapters. Benchmark model selection uses catalog contracts, not filenames. `Runtime.Compatibility` has no callers or project references and its source/project/solution entry have been removed.
- Admission scheduling consumes `ProcessorExecutionCapabilities`, including the optional model-neutral `RequiresResidentSessionAdmission` flag. Automatic limits use advertised concurrency; explicit caps can reduce but cannot exceed it. Compiled VMs retain their existing execution queues, and resident device admission is bounded by both configured residency and advertised concurrency. CPU hosts do not inherit GPU residency limits. The shared base operator profile flag is now `RequiredByBaseProfile`, with unchanged membership and no RWKV-specific public member.
- Phi4 encoder graphs are complete. `Phi4AudioGraphModule` connects feature normalization, subsampling, the full Conformer and speech/vision projectors through the registered `Processor` tensor-session entry. Synthetic FP32/FP16 weights execute on CPU and D3D12, with the default 24-layer depth additionally exercised on CPU. `Phi4VisionGraphModule` owns patch embedding, masked transformer attention/FFN, 2x2 pooling, HD gather and projection; its default 26-layer depth executes on D3D12 with synthetic weights. Vision native weights retain FP16 descriptors; linear weights support FP16 or FP32. Missing vision instruction registration and the unsupported CPU vision target are explicitly rejected before execution. These encoders are connected to the model-owned fusion/decoder entry described below; direct implementations remain for comparison. No placeholder graphs or silent CPU fallbacks are accepted.
- Target-filtered instruction collections now preserve model-owned graph mappings and dispatch callbacks, excluding mappings for other targets. VM backend preparation advertises the complete existing T0 contract catalog, including matrix multiplication, affine and bias-add, without model-specific branches or native overrides of standard semantics. FP16 component weights retain their storage descriptors and explicit FP32 cast nodes; flat kernel ports use validated dense tensor views and graph IR version 2.
- Model-owned audio/vision mappings declare correct row/head work-group dispatch for normalization and attention, rather than using an elementwise grid for every operator. Generic VM index bounds now validate complete Int32 arrays and allow an instruction to declare a finite negative reserved range (default minimum 0). HD gather declares -1/-2 separator values and a flattened patch-table bound; task and upload paths reject invalid values anywhere in the mapped array before GPU execution, including offset subviews. The direct vision comparison program uses the equivalent flattened HD input descriptor.
- The model-owned multi-file catalog and graph/port ABI are implemented: `Phi4ModelPackage` owns text, omni, vision-LoRA and speech-LoRA GGUF files plus the tokenizer; the direct text session has packed control inputs and a default context capacity of 4096. Legacy fusion ports declare FP32 `[tokenCount, 3072]` with layout `token-major`, whereas the VM graph binding adapter explicitly supports `dense`. The model-owned compatibility boundary validates identical contiguous token-by-width storage without whitelisting a model-specific layout in shared code.
- `Phi4PackageTensorCatalog` and `Phi4PackageGraphReader` now provide a model-owned multi-file graph catalog: text, omni and both adapters have explicit scopes; omni component aliases retain the existing encoder weight keys. Tensor data is borrowed without full FP32 catalog copies, and generated RoPE frequencies are model-owned FP32 resources. Successful catalog construction transfers source ownership; disposal releases every distinct source even when one fails, while metadata remains inspectable and data spans become invalid. Synthetic tests cover these rules; real GGUF package execution is still deferred.
Shared `GraphTensorView` still rejects cross-element-type reinterpretation. The completed decoder consumes these typed ports rather than packed controls.
Actual compiled CPU integer-state execution, failure recovery and reset are covered without Phi4 branches in shared code. Phi4 decoder mappings now explicitly preserve both KV cache ports as read/write state.
- Step 7 is complete for the planned synthetic graph scope. `Phi4ModelGraphModule` is the registered `phi4` entry and composes model-owned text, audio/vision encoders and dense embedding fusion without shared model branches. `Phi4TextGraphModule` executes RMS normalization, tied embedding/logit projection, RoPE, stateful GQA/KV caches, SwiGLU and both adapters on CPU/D3D12; the 32-layer depth is additionally covered on CPU. Package-owned LoRA alpha is divided by each matrix's rank; missing alpha is rejected unless an explicit scale is supplied. Native GPU mappings reuse existing transformer shaders, with model-owned read/write cache signatures, position bounds and reduction dispatch.
- `Phi4FusionGraphModule` validates exact prompt coverage and connects contiguous FP32 token-by-width encoder ports through generic copies and gathers. Reserved media placeholders are not used as vocabulary indices. The explicit model-owned legacy `token-major` descriptor conversion describes identical row-major storage; shared graph views still accept only `dense`. A fused prompt's descriptor-bound state continues through the token decoder without reencoding. The combined encoder/fusion graph is a correctness path that recomputes encoders per invocation; cached encoder execution is a separate component scheduling concern, not a hidden fallback.
- The new multi-output cache kernels exposed a generic D3D12 hazard-accounting defect: later write ports incorrectly treated the same operator's earlier write ports as prior cross-thread producers. Hazard checks now compare reads with writes from prior operators; separate non-pointwise operators still require dispatch isolation. Independent native-state GPU tests cover both cases.
- Step 12 is complete: all shared assembly references and model-named public members are guarded, the persisted full solution builds, the available-input migration regression passes, original RWKV snapshots are unchanged, and transitional compatibility sources/project references are removed. Direct Phi4 implementations remain as comparison implementations, and real Phi4 model validation remains deferred.
